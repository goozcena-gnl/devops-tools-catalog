# DevOps Tools Catalogue v0.5.0

## Overview

v0.5.0 is a substantial backward-compatible catalogue and reliability release. It combines 138 net canonical additions, large-scale evidence-reviewed reconciliation, targeted identity and licensing remediation, stronger historical provenance, and hardened network and link verification. It covers the accepted work in PRs #47 through #57 without changing the catalogue schema or consumer contract.

## Catalogue growth

The canonical catalogue grows from 1,285 to 1,423 records, a net gain of 138:

- 20 prioritized additions from the Stéphane Robert audit in PR #47;
- 1 Headlamp core addition in PR #52; and
- 117 September Wave 4 additions in PR #54.

The arithmetic reconciles exactly: `20 + 1 + 117 = 138`. No canonical records were deleted.

## September Wave 4

Wave 4 accounted for all 152 submitted occurrences across 145 semantic identities:

- 117 additions;
- 11 updates to existing records;
- 7 duplicate submissions;
- 15 out-of-scope submissions;
- 2 candidates held pending evidence; and
- 0 unaccounted occurrences.

The review distinguished Azure kubelogin from int128 kubelogin, reconciled Python with CPython, disambiguated the submitted Superset identity, and reviewed 20 URL aliases. Kubiya and portkube were held in the reconciliation ledger rather than guessed; they are not canonical records in this release.

## Evidence and provenance improvements

The accepted work prioritizes primary evidence over discovery-source descriptions. Reviews corrected upstream identities and product, component, community, enterprise, and licensing boundaries, including the ALTCHA self-hosted core and commercial layers, Steampipe source distribution and vendor binaries, Pangolin Community and Enterprise guidance, and LocalStack, MinIO, OpenObserve, GitGuardian, and ggshield distinctions.

Historical migration provenance was restored for reconciled records, with regression coverage requiring every legacy occurrence to map to its canonical source. Aliases are retained only where identity continuity is justified, and uncertain facts remain visible for later review instead of being inferred.

## Link-audit reliability

Strict auditing distinguishes reviewed known debt from new regressions: `blocking_known` records accepted review debt, while `blocking_new = 0` is the release gate. Current endpoint repairs include Firecracker documentation, DevOps Interview Questions, and OWASP DockSec, Amass, and Dependency-Check; historical source URLs remain provenance rather than being rewritten as current evidence.

At release-preparation validation, two fresh audits and one compatible cached audit each reported four observed known blockers, zero new blockers, five apparent baseline resolutions, and `PASS` across 2,407 URLs. Broad GitHub rate limiting or access restriction affected those five baseline URLs, so the preparation does not treat them as genuinely resolved; the reviewed baseline remains nine.

## Security and transport hardening

The checker now supports cookie-aware redirects and bounded retry of explicitly identified TLS EOF transport failures. Certificate validation remains strict, exhausted TLS failures remain blocking, and there is no insecure TLS bypass or HTTPS-to-HTTP fallback.

When a ranged fallback returns HTTP 206, the checker performs an ordinary GET confirmation so a partial response cannot conceal the normal endpoint's 404. Cache semantics advance to version 4, invalidating older cached conclusions produced before this confirmation behavior.

## Validation and governance

Release preparation passed Ruff lint and format checks, 435 automated tests, deterministic generated-document verification, catalogue validation, and Git whitespace checks. The catalogue contains 1,423 unique IDs across 30 taxonomy categories.

Repository issue #2 remains open for unresolved catalogue URL review. There are 959 canonical records explicitly marked as requiring review and nine reviewed known link blockers. This release does not claim that every record is fully reviewed, every URL will remain healthy, or all known link debt is resolved.

## Upgrade and adoption impact

v0.5.0 is backward compatible and requires no schema migration. Consumers that snapshot catalogue contents should refresh derived data for 1,423 canonical records. Maintainers using link-audit caches should expect results under older semantics to be invalidated automatically by cache version 4.

At v0.5.0 release-preparation review time, no v0.5.0 tag or GitHub Release had been created. Publication requires a separate owner-approved action after this preparation is reviewed and merged.
