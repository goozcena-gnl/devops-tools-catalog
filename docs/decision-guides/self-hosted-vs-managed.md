# Self-hosted versus managed services

Evaluate each capability independently rather than making one policy for the entire stack.

| Consideration | Self-hosted | Managed |
|---|---|---|
| Control | Infrastructure, data, versions, and customization | Contract and provider controls |
| Labour | Capacity, upgrades, backup, security, and on-call | Integration, vendor management, and cost governance |
| Economics | Efficient at scale with capable operators | Efficient when specialist operating work is scarce |
| Exit | Data and configuration under direct control | Requires tested export and migration paths |

Self-host when regulation, customization, locality, or scale economics justify full lifecycle ownership. Choose managed when availability and specialist operations are not differentiators. Include engineering labour, incident exposure, egress, retention, and exit costs in the comparison.
