## 3. Evidence methodology

- Planning CSV rows for Batch B are immutable scope.
- Canonical YAML remains the source of truth for final values.
- HTTP status, redirect chains, repository-archival flags, and popularity signals are triage inputs only; they are not sufficient to determine whether a product is active or deprecated.
- Repository archival does not imply product retirement. Product lifecycle and repository status are evaluated separately.
- A canonical `repository_url` may move to an official cold-storage or retirement location only when ownership continuity is directly proven by primary sources belonging to the same project governance or vendor.
- An unofficial fork or community mirror is not an acceptable replacement without an explicit official migration statement.
- When evidence remains inconclusive, the original canonical value is preserved and the unresolved boundary is documented.

## 4. Evidence policy

Accepted primary sources:
- Official project or vendor documentation
- Canonical organization repositories under the same GitHub ownership
- Repository archive and README notices from the owning organization
- Official migration, retirement, acquisition, or deprecation notices from the project maintainers
- Official release or maintenance announcements
- Official product pages

Not accepted as sole evidence:
- Secondary search results
- HTTP status codes or redirect chains
- Fork popularity or community usage
- Absence of recent commits or releases
