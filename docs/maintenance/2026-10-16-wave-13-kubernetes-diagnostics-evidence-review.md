## Evidence method and dispositions

Actual upstream licence files establish the software grants. READMEs, configuration/source paths and release notes establish operational boundaries. Maturity labels are conservative maintainer judgments about the documented workflow and distribution surface; they do not certify production suitability, provider compatibility or support SLAs. No project was rated by stars, visibility, HTTP status or commit recency alone.

**Nine CLEAR REVIEW; one RETAIN REVIEW — SPECIFIC UNRESOLVED BOUNDARY (`kube-hunter`).** The latter has a verified Apache-2.0 grant and explicit cessation notice, but current Kubernetes support/compatibility and the legacy reporting service remain unestablished. No active status or known maturity is fabricated.

## Cross-record boundaries

- kubeconform validates schemas; kube-score recommends reliability/security practices; Kubesec assigns security risk points. None independently implements every server-side check or admission policy.
- Popeye inspects deployed resource hygiene read-only; kube-hunter performs authorized legacy attack-surface probing and optional active exploitation.
- Kor reference rules can produce false positives and optional deletion is separate from discovery.
- kubectx/kubens select kubeconfig context/namespace; Kubernetes authentication and RBAC remain separate.
- kubectl-ai tool confirmation is not authorization or proof of command safety; model data/cost boundaries are independent of cluster permissions.
- KubePlumber creates diagnostic workloads and tests selected paths, not comprehensive network security.
- KubeView visualizes live resources; it is not an authorization layer, configuration validator or monitoring storage backend.
