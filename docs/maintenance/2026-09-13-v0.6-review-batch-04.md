## Method

Review used current official product or project sites first, followed by official
documentation, canonical repositories and licence files, pricing or licensing pages,
lifecycle and rebrand material, and official repository metadata. Existing `legacy:`
provenance was preserved and fresh primary sources were added.

Licence follows the catalogue adoption identity. Hosted and commercial platforms do not
inherit licences from agents, SDKs, CLIs, integrations, providers, or upstream components;
standalone software does not inherit a vendor's commercial model. Proprietary services with
free quotas remain `commercial`; `free-saas` is used for Flathub because the adoption identity
is the community-run free hosted repository. SPDX values were added only where the exact
standalone repository licence supports them.

Lifecycle changes require first-party evidence. Current documentation established active
status for the resolved identities, so this batch contains no lifecycle correction. A stable
ID that combines a vendor, product family, feature, historical project, or adjacent component
remains an `IDENTITY_BLOCKER`; unknown values are retained rather than inferred. Review can
also correct evidenced fields while retaining review when a material boundary remains
undocumented, as for EveryDev.ai.

## High-risk identity findings

### docker-swarm

Docker documents current Swarm mode as integrated into Docker Engine and built with SwarmKit,
while the old standalone classic Swarm repository is archived. The inherited record does not
say which adoption identity it represents. It remains an identity blocker without a repository
or licence pending separate stable-ID reconciliation.

### entrust-keycontrol

Entrust acquired HyTrust, and the current key-management page explicitly labels Entrust
Cryptographic Security Platform Key Manager as formerly KeyControl. The stable ID can remain;
the current name, ownership, URLs, commercial boundary, and active state are now explicit.

### everydev-ai

Current first-party pages establish a live AI developer-tool directory and comparison surface.
They do not provide a canonical software repository or authoritative product-level licensing
boundary. Status and service evidence were refreshed, but licence and maturity remain unknown
and review remains open.

### f5-waf-for-nginx

F5's current product and documentation use F5 WAF for NGINX and explicitly identify NGINX App
Protect WAF as the former name. It remains a current commercial NGINX security product, distinct
from both NGINX OSS and F5 Distributed Cloud WAAP.

### filigran

Filigran is a vendor/XTM platform umbrella spanning OpenCTI, OpenAEV (formerly OpenBAS), and
other products. No separate OpenCTI or OpenBAS record currently resolves that overlap. The
umbrella does not inherit OpenCTI's mixed licence and remains an identity blocker for a separate
reconciliation task.

### flathub

Flathub documentation describes a community-run centralized public service for Flatpak apps.
The catalogue adoption identity is that free hosted repository, not Flatpak and not one website
codebase, so it is modelled as `free-saas` without a canonical product repository or SPDX value.

### futurfusion

The current site, official GitHub organization, and Dell marketplace evidence establish the
spelling, vendor continuity, and active commercial virtualization suite. The suite uses and
publishes open-source components, but those repositories do not license the product identity.

### garage-webui

Garage WebUI is an independently maintained third-party containerized administration UI for
Garage, not the Garage server or an official Garage subsystem. Its own canonical repository and
MIT licence establish a separate OSS adoption decision.
