# DevOps Tools Catalogue v0.4.0

## Overview

v0.4.0 combines a substantial evidence-reviewed catalogue expansion with strict link-audit regression hardening and targeted catalogue remediation. It is a backward-compatible release candidate built from the accepted work in PRs #43, #44, and #45.

## Catalogue growth

The canonical catalogue grows from 1,229 to 1,285 records, adding 56 canonical records.

Wave 3 reconciled 62 submitted occurrences across 61 semantic identities:

- 56 additions;
- 3 evidence-backed updates to existing records;
- 1 already-correct existing identity;
- 1 duplicate;
- 1 out-of-scope educational reference implementation;
- 0 unresolved or unaccounted occurrences.

Coverage expands across Kubernetes operations and managed Kubernetes, DNS and network infrastructure, backup and synchronization, IAM and OIDC, source control and developer tooling, security, observability, FinOps, and Kubernetes or AI infrastructure.

## Link-audit reliability

Strict auditing now distinguishes reviewed known debt from new regressions. `blocking_known` identifies previously reviewed blockers, while `blocking_new` determines whether a strict run fails.

Archive-state awareness, cache compatibility with audit context, and HEAD-to-ranged-GET fallback behavior reduce false conclusions and stale-cache reuse. Targeted remediation resolved the Floci-AZ, Datree, and CAI regressions without adding them to the reviewed blocker baseline.

## Evidence-first review

Candidate reconciliation used current primary sources for upstream ownership, licences, offering models, lifecycle state, and operational capability. Review explicitly handled product versus component boundaries, authoritative upstreams versus mirrors, and materially distinct managed-service choices.

Notable decisions include reconciling OpenStack Magnum to its authoritative OpenDev upstream, correctly scoping Snyk CLI licence evidence away from the commercial platform, retaining Pulumi's open-core boundary, and correcting Canonical Kubernetes and Ansible `kubernetes.core` licence metadata. Independent adversarial review also removed unsupported Kairos and AFFiNE taxonomy assignments before merge.
