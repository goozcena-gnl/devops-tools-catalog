# DevOps Tools Catalogue v0.3.0

## Overview

v0.3.0 expands the canonical DevOps Tools Catalogue to 1,229 records. It combines two major evidence-reviewed candidate waves while preserving the existing schema and deterministic documentation workflow.

## Catalogue growth

- 137 canonical records added since v0.2.2: 54 through PR #39 and 83 through PR #40.
- Broader coverage across DevOps, Kubernetes, security, observability, platform engineering, developer tooling, infrastructure, and AI-related tooling.
- Evidence-backed corrections applied to existing records without a breaking schema or API contract change.

## Evidence-first review

Candidate decisions were reconciled against primary evidence, with explicit treatment of duplicates, aliases, hosted services, OSS and open-core offerings, commercial availability, SPDX licensing, and lifecycle status. Independent semantic review and focused remediation were completed before merge.

## Validation and governance

Release preparation passed Ruff lint and format checks, the full automated test suite, deterministic documentation verification, catalogue validation, and Git whitespace checks. Contributor guidance now reflects both Ruff checks enforced by CI.

## Remaining evidence boundaries

- The RepoD candidate remains held as `NEEDS_REVIEW` because authoritative upstream repository, licence, and ownership evidence is insufficient.
- Repository issue #2 remains open for unresolved catalogue URL review.
- Branch-protection controls remain unavailable for this private repository on the current GitHub plan.

This release does not claim that all catalogue evidence debt is resolved.

## Upgrade and adoption impact

This is a backward-compatible catalogue expansion. Consumers can adopt v0.3.0 without schema migration; generated indexes and documentation retain their existing structure. Integrations that snapshot catalogue contents should expect 1,229 canonical records and refresh their derived data after upgrading.
